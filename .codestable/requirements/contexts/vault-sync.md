# 保险库与分片同步领域上下文

把用户的配置文件集合当作保险库，在本地与私有 GitHub Gist 之间做多设备同步，并可选启用按文件的端到端加密。

## 通用语言

**配置文件（NexusFile）**：用户维护的单个文本配置；聚合根，封装文件名生成（`id` + 语言 → 文件名）与脏状态跟踪。

**根索引（NexusIndex）**：远程 `nexus_index.json`，维护文件清单与分片描述符。

**分片（Shard）**：远程存储单元，每个分片一个 gist 与一份分片清单。

**分片清单（ShardManifest）**：单个分片内的文件清单，记录 fileId、filename、checksum、size、isSecure。

**同步头（SyncHead）**：持久化的同步基准，用于启动时判断是否需要拉取。

**智能同步 / 强制全量拉取**：前者用增量元数据确定最小拉取集合；后者跳过时间与同步头捷径，重建 index 中的全部分片。

**安全模式 / 保险库**：可选的按文件 E2EE；保险库密码经 PBKDF2 派生密钥，用于 AES-GCM 加解密。

**分类**：工作区中组织配置文件的容器；删除分类属于破坏性操作。
_避免_：分片（分片是远程存储单元，分类是本地组织单位）

**恢复点**：破坏性操作前对本地文件、历史、索引和缓存建立的内存快照，用于失败回滚。

## 稳定规则

- 远程只保存配置文件数据与索引；保险库密码绝不上传，仅暂存于会话或可信设备。
- 内容相同的判定不能只看 32-bit 校验和：跳过分片下载要求校验和与字节数同时一致；manifest 未记录字节数的旧数据按宽松处理，不重拉。
- 推送前必须通过冲突守卫：远程存在时以首次提交返回的远程时间串接后续检查，最终索引提交前比对远程 index 内容；判定冲突时中止写入，不覆盖远程。
- 破坏性操作（删除分类、强制全量拉取）不得绕过冲突检查；拉取前建立恢复点，任一步失败恢复全部本地状态，恢复失败必须以携带原始错误与恢复错误的组合错误显式报告。
- 只更新索引的推送不得产生与真实分片状态不一致的同步头。
- 历史快照随保存自动生成；读取以本地优先，本地为空时才从远程导入。
