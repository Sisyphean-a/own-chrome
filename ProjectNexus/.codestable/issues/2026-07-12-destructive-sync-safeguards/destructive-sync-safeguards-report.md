# 破坏性同步操作保护 Issue Report

## 1. 问题现象

存在两个需要处理的数据保护问题：

1. 多设备数据不同步时，在旧设备删除本地看到的最后一个分类，远程较新的数据可能从当前工作区索引中消失。
2. 确认强制拉取后，如果远程读取或解析失败，本地文档缓存、索引和历史已经被清除，只能依赖后续重新拉取。

“修复并清理旧存储”删除未引用远程分片是既有专门设计，不在本 issue 范围内。

## 2. 复现步骤

### 场景 A：删除最后分类

1. 设备 A 保留只有一个分类的旧工作区状态。
2. 设备 B 更新同一远程工作区。
3. 设备 A 不先同步，删除本地最后一个分类并确认操作。
4. 观察到：远程工作区索引可能被设备 A 的空分类状态覆盖。

复现频率：满足陈旧本地状态与最后分类条件时稳定；为避免破坏真实远程数据，本次未执行破坏性集成复现。

### 场景 B：强制拉取失败

1. 本地存在文档缓存与历史记录。
2. 发起“强制拉取覆盖”。
3. 在远程索引读取、解析或分片下载阶段发生失败。
4. 观察到：操作报错，但此前的本地数据已经被清除。

复现频率：远程拉取在本地清理后失败时稳定；本次通过静态调用顺序确认，未注入生产远程故障。

## 3. 期望 vs 实际

**期望行为**：删除分类必须尊重远程冲突检查，不应以陈旧空状态覆盖更新后的远程数据；强制拉取失败时，本地原数据应保持可用或被完整恢复。

**实际行为**：删除最后分类存在绕过冲突检查的覆盖路径；强制拉取在远程同步成功前清除本地数据，失败后没有恢复步骤。

## 4. 环境信息

- 涉及模块 / 功能：工作区分类删除、远程同步、强制拉取、本地持久化
- 相关文件 / 函数：`WorkspaceFacade.deleteCategory`、`SyncService.pushIndex`、`SyncFacade.forcePullWorkspace`、`SyncFacade.clearLocalDataForForcePull`
- 运行环境：当前代码分支，静态审计与自动化测试环境
- 其他上下文：保留“修复并清理旧存储”的账户级清理设计，不纳入改动

## 5. 严重程度

**P0** — 删除最后分类在多设备陈旧状态下可能覆盖远程工作区索引；强制拉取问题本身为 P1，但与远程数据保护修复合并处理。

## 备注

目标改动限定为：修复分类删除的冲突保护；为强制拉取增加失败恢复机制；不修改远程分片清理的既有语义。
